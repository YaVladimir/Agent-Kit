# Архитектура TodoServer

## Поток запроса

HTTP-запрос -> `TodoController` -> `TodoService` -> `TodoRepository` -> H2/JPA.

## Правила

- Контроллеры должны оставаться тонкими и делегировать поведение в
  `TodoService`.
- Доступ к persistence должен идти через `TodoRepository`.
- Для применения частичных изменений из `TodoDto` нужно переиспользовать
  `TodoMapper`.
- Новое todo-поведение обычно начинается в `TodoService`; маршрут в controller
  добавляется только если поведение должно быть доступно извне.
- Если сущность не найдена, использовать `EntityNotFoundException` и сохранять
  существующее HTTP 404 поведение.

## Известные проблемы, которые стоит учитывать

- В `TodoService#getTodo` одно сообщение exception выглядит как mojibake после
  чтения или сохранения русской строки в неверной кодировке.
- Удаление использует `GET /todo/delete/{id}` вместо HTTP DELETE-маршрута.
- В просмотренном дереве нет видимых автоматических тестов.
