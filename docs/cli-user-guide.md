# Инструкция пользователя GigaCode CLI

Эта инструкция для разработчика, который работает с GigaCode в продуктовом
репозитории.

## Как запускать

Открой терминал в корне репозитория:

```bash
cd /path/to/repo
gigacode
```

Если корпоративный CLI использует другой способ запуска, смысл тот же: запускать
его нужно из корня проекта, где лежат `AGENTS.md`, `QWEN.md`, `.context` и
настройки MCP/LSP.

На macOS M4 и Linux команды в документации считаются shell-командами для
`zsh`/`bash`. Если путь содержит пробелы, оборачивай его в кавычки:

```bash
cd "/path/with spaces/repo"
gigacode
```

## Как ставить задачу

Пиши задачу обычным языком:

```text
Добавь поле deadline к Todo. Сначала найди правильные места изменения и покажи
план. Код пока не меняй.
```

Для бизнес-задач пиши так, как сказал бы продакт:

```text
При поиске Todo нужно уметь фильтровать задачи по статусу выполнения и цвету.
Сначала проверь, есть ли уже похожая логика.
```

## Хороший формат запроса

```text
Задача: ...

Ограничения:
- сначала план;
- использовать существующие паттерны;
- код менять только после плана;
- тесты добавить или объяснить, почему их нет.
```

## Что должен сделать агент

Нормальный первый ответ агента должен содержать:

1. Задачу простыми словами.
2. Тип задачи.
3. Какие MCP/LSP-инструменты он использовал или почему они недоступны.
4. Какие классы, методы и тесты нашёл.
5. План изменения.

Если агент сразу пишет код без разведки, останови его:

```text
Стоп. Сначала используй basecode MCP и .context, найди точки изменения и покажи
план без правки файлов.
```

## Как просить использовать basecode MCP

Если нужно явно проверить навигацию:

```text
Код не меняй. Через basecode MCP найди TodoService, TodoController и все места,
где используется TodoRepository. После этого кратко объясни архитектуру.
```

Если агент пишет, что MCP недоступен, попроси диагностический ответ:

```text
Покажи, какие MCP tools доступны в текущей сессии. Если basecode не виден,
объясни, какой конфиг или запуск нужно проверить.
```

## Как работать без LSP

Если LSP сломан, это не блокирует работу. Пользовательский сценарий остаётся тем
же, но в запросе можно явно сказать:

```text
LSP сейчас не работает. Используй basecode MCP, .context и обычный поиск по
файлам. Перед изменениями покажи план.
```

## Когда просить только план

Для нетривиальных задач начинай с плана:

```text
Код пока не меняй. Разбери задачу, найди точки изменения, риски и тесты.
```

После этого можно разрешить реализацию:

```text
План ок, реализуй минимальные изменения и запусти релевантные проверки.
```

## Что проверять в финальном ответе

Финальный ответ должен содержать:

- что изменено;
- какие файлы затронуты;
- какие проверки запускались;
- какие риски остались;
- что нужно проверить руками.

Если проверок нет, агент должен прямо сказать почему.
