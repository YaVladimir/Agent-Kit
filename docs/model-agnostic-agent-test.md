# Модель-независимый тест агентского workflow

Цель теста: проверить, что манифест описывает не поведение конкретной модели, а
устойчивый паттерн работы агента. Модель может быть GigaCode, Codex или другая
LLM, если вокруг неё развернуты одинаковые слои: инструкции, контекст
репозитория, навигационные tools, проверки.

## Проверяемая гипотеза

Если агент получает:

- системный workflow;
- русскоязычные инструкции репозитория;
- `.context` с обзором, архитектурой и доменными правилами;
- доступ к поиску по коду или MCP/LSP tools;

то он должен идти по одному маршруту независимо от модели:

```text
задача простыми словами
  -> тип задачи
  -> доменный контекст
  -> архитектурный контекст
  -> поиск точек изменения
  -> похожие паттерны
  -> план
  -> реализация после подтверждения
  -> проверки
```

## Dry-run сценарий

Тестовый запрос:

```text
Добавить поле deadline к Todo. Код пока не менять. Сначала найти точки
изменения и показать план.
```

## Доступные слои в тесте

- Workflow из `skills/gigacode-java-enterprise/SKILL.md`.
- Контекст TodoServer из `examples/todoserver-context`.
- Поиск по коду через локальный файловый поиск как fallback для MCP/LSP.
- Реальный LSP и `basecode-mcp-server` в этом dry-run не проверялись.

## Ожидаемое поведение агента

Агент не должен сразу писать код. Он должен:

1. Переформулировать задачу.
2. Определить тип задачи.
3. Прочитать архитектурный контекст.
4. Найти классы, которые хранят и передают Todo.
5. Найти сервисный путь создания, изменения и поиска.
6. Найти тесты или явно сказать, что тестов нет.
7. Предложить план изменения.

## Фактический результат dry-run

Агент нашёл следующие точки изменения:

- `Todo`: JPA-сущность. Нужно добавить поле `deadline`, getter, constructors и
  `toString`.
- `TodoDto`: DTO для create/update. Нужно добавить поле `deadline`, getter,
  fluent setter, constructor и `toString`.
- `TodoMapper`: MapStruct уже обновляет entity из DTO с
  `NullValuePropertyMappingStrategy.IGNORE`; при совпадении имён поле будет
  участвовать в частичном update.
- `TodoService.add`: сейчас создаёт `Todo` вручную через constructor, значит
  нужно передать `deadline` при создании.
- `TodoFilter` и `TodoService.findAll`: менять только если задача требует
  фильтрацию по deadline. Для простого добавления поля это отдельное продуктовое
  решение.
- `TodoController`: менять не нужно, если API продолжает принимать `TodoDto` в
  существующих endpoints.
- Тесты: в просмотренном дереве `src/test` не найден.

## План, который должен выдать агент

1. Добавить `deadline` в entity `Todo`.
2. Добавить `deadline` в `TodoDto`.
3. Обновить constructor вызов в `TodoService.add`.
4. Проверить, что `TodoMapper.updateTodoFromDto` подхватит поле автоматически.
5. Решить отдельно, нужна ли фильтрация по deadline через `TodoFilter`.
6. Добавить unit/controller tests или явно зафиксировать, что тестовая
   инфраструктура в проекте отсутствует.
7. Запустить `mvn test` или минимально `mvn -q -DskipTests compile`.

## Вывод

Workflow прошёл модель-независимый тест на уровне планирования. Он удерживает
агента от преждевременного кодинга и заставляет идти через контекст, архитектуру
и точки изменения.

Что не покрыто этим тестом:

- реальный tool calling GigaCode CLI;
- реальный `basecode-mcp-server`;
- LSP/JDT LS;
- качество реализации после подтверждения плана;
- запуск Maven-проверок.

## Что улучшить в kit
