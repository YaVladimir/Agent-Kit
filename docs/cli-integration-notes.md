# Заметки по интеграции CLI

Не предполагаем, что внутренний GigaCode CLI доступен локально во время
разработки этого kit.

## Стабильные допущения

- Агент может получить системный промпт или аналогичный слой инструкций.
- Агент может читать файлы репозитория.
- MCP-подобные инструменты можно отдать как настоящие MCP-серверы или как
  корпоративные CLI-инструменты с похожими контрактами.
- LSP-навигация может быть подключена самим CLI, MCP-сервером или обёрткой.

## Граница адаптера

Эти части должны оставаться CLI-независимыми:

- `prompts/*.md`
- `skills/gigacode-java-enterprise`
- структура `.context`
- YAML-схемы
- контракты инструментов в `references/tool-contracts.md`

Эти части адаптируются после знакомства с внутренним CLI:

- путь и схема конфига;
- регистрация MCP-сервера;
- переменные окружения для адреса модели;
- флаги запуска LSP;
- политика разрешённых и запрещённых инструментов.

## Контракт для Qwen/DeepSeek-like моделей

Подробный контракт адаптера описан в `docs/model-adapter-contract.md`.
Коротко: модель может быть Qwen Coder, DeepSeek-like или внутренней LLM, но
вокруг неё должен быть один и тот же слой:

- системные инструкции из `prompts/`;
- проектные инструкции из `AGENTS.md`/`QWEN.md`;
- `.context` как источник доменных знаний;
- `.context/architecture-graph.yaml` как переносимый no-Docker источник
  архитектурных связей;
- MCP-compatible tools или CLI tools с теми же контрактами;
- preflight/verify без скрытых внешних загрузок;
- русскоязычный цикл работы от задачи к плану, коду и проверкам.

Для проверки конкретного CLI/wrapper заполняй
`templates/adapter-compatibility.yaml` и копируй его в продуктовый репозиторий
как `.gigacode-adapter.yaml`.
