# Контракт адаптера модели и CLI

Этот документ фиксирует границу между Agent Kit и конкретной LLM/CLI.
Kit должен оставаться переносимым: Qwen Coder, DeepSeek-like модель,
GigaCode или другая корпоративная LLM подключаются через адаптер, а не через
переписывание промптов, `.context` и MCP-контрактов.

## Что остается стабильным

Эти части не должны зависеть от конкретной модели:

- `prompts/system.md` и `prompts/corporate.md`.
- `skills/gigacode-java-enterprise/SKILL.md`.
- `templates/AGENTS.md` и `templates/QWEN.md`.
- `.context/` в продуктовом репозитории.
- `schemas/*.yaml`.
- MCP tool contracts из `skills/gigacode-java-enterprise/references/tool-contracts.md`.
- Ручной runbook развертывания фаз 1+2.

Если меняется модель, эти файлы можно уточнять, но не нужно заводить отдельную
копию workflow под каждую LLM.

## Что делает адаптер

Адаптер — это тонкий слой в CLI или wrapper, который приводит конкретную модель
к общему агентскому контракту.

Минимальные обязанности адаптера:

1. Собрать системные инструкции из `prompts/system.md`, `prompts/corporate.md`
   и проектных файлов `AGENTS.md`/`QWEN.md`.
2. Зарегистрировать инструменты по MCP-compatible контракту или предоставить
   эквивалентные CLI tools с теми же именами и схемами входа/выхода.
3. Передать модели список доступных tools и короткое описание, когда их вызывать.
4. Поддержать stdio MCP-процессы или корпоративную замену с тем же поведением.
5. Запускать агента из корня продуктового репозитория.
6. Передавать рабочую директорию, переменные окружения и лимиты времени tools.
7. Запрещать скрытые сетевые установки, если политика проекта отключает
   внешние источники.
8. Сохранять русскоязычное общение агента с разработчиком.

## Требования к модели

Модель должна уметь:

- следовать длинным системным инструкциям;
- вызывать tools или работать через CLI-эквивалент tools;
- читать результаты tools и уточнять план;
- не начинать правку кода до сбора контекста, если задача нетривиальная;
- возвращать структурированный план и финальный отчет на русском языке;
- явно называть fallback, если MCP/LSP недоступны.

Если модель хуже держит длинный контекст, адаптер должен подавать меньше текста:
сначала workflow и tool contracts, затем `.context`, затем точечные результаты
поиска.

## Совместимость Qwen Coder

Рекомендуемый профиль:

- `AGENTS.md` и/или `QWEN.md` как проектные инструкции.
- `settings.json` с объектом `mcpServers`.
- MCP через stdio.
- LSP через `mcp-language-server` или нативный LSP CLI.
- Запуск из корня продуктового репозитория.

Для Qwen-compatible CLI достаточно адаптировать путь к `settings.json` и способ
подачи системного промпта.

## Совместимость DeepSeek-like модели

Для DeepSeek-like модели контракт тот же, но адаптер может отличаться:

- если CLI не поддерживает MCP напрямую, wrapper вызывает MCP-серверы сам и
  передает результаты модели как tool results;
- если модель поддерживает function calling, MCP tools мапятся на функции;
- если function calling отсутствует, wrapper реализует явный цикл:
  `план tool call -> выполнение tool -> результат -> следующий шаг`;
- если контекстное окно меньше, wrapper обязан агрессивнее резюмировать
  `.context` и результаты поиска.

Важно: бизнес workflow и `.context` при этом не меняются.

## Минимальный цикл агента

Адаптер должен удерживать такой цикл:

```text
задача пользователя
  -> переформулировка задачи
  -> определение типа задачи
  -> чтение доменного и архитектурного контекста
  -> навигация по коду через MCP/LSP или fallback
  -> поиск похожих реализаций и тестов
  -> короткий план
  -> реализация после достаточного контекста
  -> проверки
  -> отчет на русском языке
```

## Инварианты безопасности

- Внешние загрузки не выполняются из setup-скриптов kit.
- Разработчик устанавливает инструменты только из одобренных внутренних
  источников.
- Секреты не попадают в `AGENTS.md`, `QWEN.md`, `.context`, `.gigacode.yaml`,
  MCP-конфиги и логи.
- Tools получают минимально нужные права.
- Если tool недоступен, агент сообщает fallback и продолжает только в рамках
  безопасных возможностей.

## Acceptance checklist адаптера

- [ ] Модель отвечает разработчику на русском языке.
- [ ] Модель видит проектные инструкции из `AGENTS.md` или `QWEN.md`.
- [ ] Модель видит `.context/index.md` и `.context/architecture.md`.
- [ ] Доступен хотя бы один слой навигации по коду: MCP, LSP или fallback search.
- [ ] Для Java доступен `jdtls` или явно описан fallback.
- [ ] MCP tools имеют стабильные имена и схемы.
- [ ] Агент показывает план перед нетривиальными изменениями.
- [ ] Агент запускает проверки или объясняет, почему они недоступны.
- [ ] Setup/preflight не скачивает сторонний софт.
- [ ] Проверка проходит через `scripts/check-kit.sh` на macOS/Linux или
  `scripts/check-kit.ps1` на Windows.
