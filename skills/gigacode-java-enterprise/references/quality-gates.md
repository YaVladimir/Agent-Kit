# Проверки качества

Выбирай проверки по радиусу изменения.

## Узкие изменения

- Скомпилировать затронутый модуль.
- Запустить напрямую связанные unit-тесты.
- Запустить formatter/linter, если репозиторий этого требует.

## Изменения бизнес-правил

- Запустить service-тесты вокруг правила.
- Добавить или обновить тесты негативных сценариев.
- Проверить существующие примеры для типа исключения, кода ошибки и audit behavior.
- Обновить доменный контекст, если изменилось правило.

## Изменения общего API или архитектуры

- Запустить тесты модуля.
- Запустить integration-тесты, если менялись HTTP-маршруты, persistence или messaging.
- Запустить архитектурные проверки, если они доступны.
- Проверить references перед изменением публичных interfaces.
