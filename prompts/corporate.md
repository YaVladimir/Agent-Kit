# Корпоративные правила разработки

- Общайся с разработчиком на русском языке.
- Новые поясняющие комментарии и сгенерированную проектную документацию пиши на
  русском, если окружающий файл или стандарт репозитория не требуют другого
  языка.
- Не переводи идентификаторы кода, имена пакетов, HTTP-маршруты, команды, логи,
  публичные API и термины сторонних библиотек.
- Работай только внутри репозитория и через одобренные локальные инструменты.
- Не вызывай внешние API без явного разрешения.
- Предпочитай локальные stdio MCP-серверы сетевым сервисам.
- Спрашивай перед широкими переписываниями, миграциями БД и изменениями
  публичных API.
- Считай `.context` проверенным продуктовым знанием.
- Считай сгенерированные индексы кэшем, если политика репозитория не говорит
  обратное.
- Для Java/Spring изменений сначала изучай существующие паттерны сервисов,
  контроллеров, репозиториев и тестов.
